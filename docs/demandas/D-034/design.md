# D-034 (E1.5) Super admin + TOTP — design

## 1. Solução e alternativas
Módulo `src/server/auth/admin/` (sem `next/*`, exceto `pagina.ts`). Login em 2 etapas sobre a tabela `sessao` existente, **sem coluna nova**: o admin é reconhecido por `usuario.papel='super_admin'`; pré-sessão = `totp_verificado_em NULL` com `expira_em = criado+10 min`; sessão admin = nova linha com `totp_verificado_em` e `expira_em = min(uso+30 min, criado+8 h)`. Cookie próprio `ab_admin`.
Descartadas: (a) coluna `tipo` em `sessao` (papel já distingue); (b) reutilizar `iniciarSessao`/`validade.ts` (renova 7/30 d; proibido); (c) lib `otplib` (RFC 6238 são ~30 linhas em `node:crypto`); (d) segredo pendente em campo oculto assinado (exige chave extra de assinatura) — usa-se S-1: pendente cifrado em `totp_segredo_cifrado` com `totp_ativado_em NULL`.
**QR:** dependência exata nova `qrcode-generator` (MIT, sem I/O, sem rede), versão a fixar pelo dev (`npm view` + `save-exact`), importada só por `src/server/auth/admin/qr.ts` (regra ESLint de importação única, como sharp). Encoder próprio descartado: custo/risco > benefício. SVG montado no servidor (módulos como `<path>`), sem JS cliente; fallback: chave base32 agrupada em 4.
S-1..S-5 validadas (S-1 aceita: reaproveita o pendente em reload, não regera; assim o POST sem JS sobrevive). S-4: ações admin só sob `/admin/**`.

## 2. Componentes (caminhos)
- `totp.ts` (puro): `base32`, `gerarSegredo()`, `codigoDoPasso(seg, passo)`, `passoDe(agora)=floor(ms/30000)`, `verificarCodigo(seg, codigo, agora): passo|null` (±1, `timingSafeEqual`, só `^\d{6}$` após aparar espaços/hífen; sem I/O), `uriOtpauth(email, segredo)`.
- `cifra.ts` (puro + `node:crypto`): `cifrarSegredo(seg, usuarioId, chave)`/`decifrarSegredo(...)`; formato `v1:<iv>:<tag>:<cifra>` base64url, AES-256-GCM, IV 12 B, AAD=usuarioId; `lerChave(env)` aceita base64 ou 64 hex, exige 32 B (lança sem citar o valor). Única leitura de `process.env.ADMIN_TOTP_CHAVE` via `src/config/env.ts` (campo opcional no schema; obrigatório em produção e se existir super admin via check-env).
- `validade-admin.ts` (puro): `PREAUTH_MS=10min`, `INATIVIDADE_ADMIN_MS=30min`, `TETO_ADMIN_MS=8h`, `expiracaoPreauth`, `expiracaoAdmin(criado, agora)`, `precisaRenovarAdmin` (≥ 1 min desde o último uso, evita escrita por request).
- `cookie-admin.ts` (puro, importável pelo proxy): `NOME_COOKIE_ADMIN='ab_admin'`, atributos httpOnly/SameSite=Strict/Path=/admin/Secure só em produção/Max-Age 8 h (pré-sessão: 10 min).
- `sessao-admin.ts`: `iniciarPreSessao`, `promoverSessao` (cria nova, revoga a pré, na MESMA transação do `login.sucesso`), `encerrarSessaoAdmin`.
- `login-admin.ts`: `entrarAdmin({email,senha})` (etapa 1: valida → rate limit `admin-login:`+SHA256(email), 10/15 min via `incrementarJanela` como `login.ts`; hash fictício; mensagem única "E-mail ou senha incorretos."; não-admin ou inexistente = mesma recusa; sucesso devolve `{token, etapa:'totp'|'cadastro'}`; só a pré-sessão nasce, **sem** auditoria de sucesso), `verificarTotpAdmin(token, codigo, agora)`, `cadastrarTotp(token, codigo, agora)`, `obterCadastroTotp(token)` (gera/reaproveita pendente; devolve segredo+SVG só para render).
- `garantir-super-admin.ts`: `garantirSuperAdmin({email,senha}, deps?)`: valida (e-mail minúsculo, senha 12–1024), hash antes da transação, `INSERT … ON CONFLICT (email) DO NOTHING RETURNING id`; sem linha → `SELECT papel`: `super_admin` → `'existente'` (nada alterado), outro papel → `ErroContaNaoAdmin`. Repo: `src/server/repos/admin.ts` (pré-contexto; únicos acessos a `usuario` do admin).
- `pagina.ts`: `exigirAcessoAoAdmin(caminho)` → `{tipo:'permitido', ctx: AdminContext} | {tipo:'negado'}`; fluxo RN-10: sem `ab_admin` → se há `ab_sessao` de salão válida (`resolverTenant`) → negado (403), senão `redirect('/admin/entrar')`; pré-sessão válida → `redirect` para `/admin/entrar` (etapa 2/cadastro conforme `totp_ativado_em`); redirect sempre fora de try/catch.
- `src/server/tenant/sessao.ts`: **alterar** `sessaoDaCredencial` para (i) não renovar quando `papel==='super_admin'` e (ii) aplicar a política admin (renovar via `renovarSessaoAdmin` com `min(uso+30m, criado+8h)`; `buscarSessaoValida` já filtra `expira_em`). `resolverTenant` com sessão admin → `AcessoNegado` sem renovar; teste prova que `validade.ts` do salão não foi tocado.
- Auditoria: estender `ACOES_AUDITAVEIS` com `login.sucesso`, `totp.cadastrar` (entidade `usuario`; fora de `ACOES_COM_ANTES_DEPOIS`; `depois` = `{ metodo:'totp' }`/`{ etapa }`, nunca segredo). Atualizar testes de vocabulário.
- Páginas: `src/app/admin/entrar/page.tsx` (+`acoes.ts` shell `'use server'`; etapa por cookie de pré-sessão: formulário senha, formulário código, ou cadastro com `<svg>` + chave em texto; `force-dynamic`, `no-store`), `src/app/admin/page.tsx` (nome/e-mail + "Sair" POST; `Cache-Control: no-store` via `next.config.ts` headers `/admin/:path*`), `src/app/admin/sair/` ou ação `sair`. Ações com `defineAcao`: **não**; são pré-contexto (como `/entrar`): sem `*.acao.ts` para entrar/cadastro. A ação `sair` do admin é shell que lê o cookie e chama `encerrarSessaoAdmin`. Futuras ações admin (E8.2) usam `exigirAcessoAoAdmin`/`resolverAdmin`.
- `src/proxy.ts`: ampliar matcher p/ `/admin`, `/admin/:path*`; exceto `/admin/entrar` (e `/admin/sair` POST segue); só confere presença de `ab_admin`, senão 307 `/admin/entrar` — **mas** gestor logado sem `ab_admin` precisa de 403 (CA-4): o proxy deixa passar `/admin/**` se existir `ab_sessao` (a página decide 403); sem nenhum cookie → 307. Sem Prisma no proxy.
- `src/config/navegacao.ts`: `/admin` já em `SEGMENTOS_RESERVADOS` (só teste que garante).
- `src/scripts/superadmin-criar.ts` + `package.json`: script `superadmin:criar` (`build:node` + `node --env-file-if-exists=.env dist/scripts/superadmin-criar.js`), entrada adicionada ao esbuild de `build:node`; lê `SUPERADMIN_EMAIL`/`SUPERADMIN_PASSWORD`, imprime só `criado|existente`, exit 0; erro → exit 1 sem a senha.
- Vitrine `src/app/dev/admin-entrar/page.tsx` (404 sem `VITRINE_COMPONENTES=true`/dev; `ROTAS.devAdminEntrar`) com ação só de validação de formato; E2E `e2e/admin-entrar.spec.ts` + `-sem-js`.

## 3. Interfaces-chave
```
garantirSuperAdmin(e:{email:string;senha:string}): Promise<'criado'|'existente'>
entrarAdmin(e,{agora?,verificarSenha?}): Promise<{ok:true;token;etapa:'totp'|'cadastro'}|{ok:false;motivo:'validacao'|'recusado';...}>
verificarTotpAdmin(token,codigo,{agora?}): {ok:true;token}|{ok:false;motivo:'invalido'|'limite'|'sessao'}
cadastrarTotp(token,codigo,{agora?}): idem; recusa se totp_ativado_em preenchido
```
**Ordem em `verificarTotpAdmin`:** formato (sem banco) → `incrementarJanela('admin-totp:'+sha256(usuarioId))` > 5 ⇒ `limite` (sem verificar; vale mesmo com código certo) → decifra → `verificarCodigo` → UMA transação READ COMMITTED: `UPDATE usuario SET totp_ultimo_passo=$p WHERE id=$u AND (totp_ultimo_passo IS NULL OR totp_ultimo_passo<$p)` (0 linhas ⇒ `invalido`, replay) → cria sessão admin (nova linha) + revoga a pré → `registrarAuditoria(criarAdminContext(id), login.sucesso, r)`. Falha de passo/código: `registrarFalhaAuditoria` em conexão própria **após** o rollback (no catch fora da transação), `atorEmailInformado` truncado; nunca código/senha. Só sucesso devolve a reserva? NÃO: no TOTP não se devolve (5 falhas contam; sucesso decrementa 1 para não punir uso legítimo, depois da transação). Senha errada: `login.falha_senha` do mesmo modo.
`cadastrarTotp`: verifica o pendente decifrado; transação: `UPDATE … SET totp_ativado_em=$agora, totp_ultimo_passo=$p WHERE id=$u AND totp_ativado_em IS NULL AND totp_segredo_cifrado=$lido` (1 vence) + promove sessão + auditoria `totp.cadastrar` e `login.sucesso`. Pendente criado por `UPDATE … SET totp_segredo_cifrado=$c WHERE id=$u AND totp_ativado_em IS NULL AND totp_segredo_cifrado IS NULL` e relido (corrida: ambos veem o mesmo).

## 6. Invariantes
Escopo por salão: n/a (plataforma; `AdminContext` recusado pelos repos de tenant; `resolverTenant` recusa admin e vice-versa, CA-14). Exclusão anti-sobreposição: n/a. UTC: passos TOTP em epoch, relógio injetado, testar em UTC e America/Sao_Paulo. Adaptadores: n/a (QR local; nenhuma integração). Soft delete/anonimização: n/a. Salão suspenso: n/a. Idempotência: script idempotente; anti-replay atômico; cadastro 1 vence. Auditoria super admin: `login.sucesso`/`totp.cadastrar` na transação; falhas em conexão própria após rollback. Cookies/CSRF: SameSite=Strict + Origin do Next nas Server Actions.

## 7. Riscos
R-1 Perda/troca da chave invalida todos os TOTP (README + reset manual). R-2 Proxy deixa passar `/admin/**` com `ab_sessao` para 403 correto: a autorização real é na página (documentar). R-3 Sessão admin sem coluna de tipo: a distinção por papel depende de nunca mudar o papel de um usuário com sessões (garantir: `garantirSuperAdmin` não altera papel). R-4 `qrcode-generator`: dependência nova, fixar versão, revisar licença/audit. R-5 Rate limit de TOTP penaliza sucesso: decremento após sucesso. R-6 Escrita de renovação a cada minuto: UPDATE condicional por `ultimo_uso_em`.

## 8. Testes
Unit: totp (vetores RFC, ±1, formato — CA-6), cifra (CA-5), validade-admin (CA-9, relógio injetado), cookie, qr (SVG sem `http`), garantir validações, vocabulário. Integração (PostgreSQL real, `tests/integration/admin/`): CA-1 (2× e 10 paralelas; gestor existente), CA-2/3/7/8/9/10/14, concorrência (replay ×2, cadastro ×2), auditoria na transação (falha desfaz sessão), rate limit, guarda (CA-4 com gestor/profissional), script via processo filho (CA-1 exit 0, sem senha na saída), check-env (CA-11, unit). Playwright sem banco (CA-13, CA-2 sem JS parcialmente via vitrine; axe 4.14.0, 375×812). Cobertura ≥ 90% mantida: módulos puros isolados e testados.
